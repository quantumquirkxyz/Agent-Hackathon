## What changed

- **Board views.** The five API-created views were named shells with no filter and no visible
  fields. They now carry the filters that make them operational, set through
  `updateProjectV2View`:
  - Planning — `label:"wayfinder:map","wayfinder:grilling","wayfinder:research","wayfinder:prototype","wayfinder:task","spec"`
  - Execution Board — excludes those labels, board layout, showing Status, Assignees, Priority,
    Size, Sprint, Risk, Milestone, Sub-issues progress and Linked pull requests
  - Blocked — `status:Blocked`
  - Review — `status:Review`
  - Roadmap — excludes planning artifacts, roadmap layout
- **Board README.** Rewritten to record the Scrumban cadence (two-week timeboxes, WIP limit two
  per person), the six-value `Status` flow, the lean field schema with no `Phase` field, the
  view table, the Ready and Blocked gates, and the honest limitation that the API cannot
  configure automation rules or view grouping.
- **`docs/reference/agents/index.md`.** Binds work items to project 27 and replaces the
  `Phase`/`Iteration` rules with `Status`/`Sprint`.
- **`docs/reference/agents/work-item-format.md`.** Replaced the invented target-shape fields
  (`work_type`, `repo_scope`, `phase`, `release_train`) with the board's real schema and added
  the board binding section.

## Residual risk

- The Execution Board is not yet grouped by `Status`: grouping and any sort order cannot be set
  through the API (`ProjectV2ViewConfigurationInput` only accepts `visibleFieldIds`), so the view
  needs a one-time human step in the GitHub UI before it renders as a Status flow.
- Auto-add and close-to-Done automation rules remain unconfigured by design; the README states
  they belong in the GitHub UI or an Actions workflow.
- ADR-0021 is still only on the unmerged local branch `chore/governance-index`, so the repo docs
  state the six `Status` values as the board's definition; the ADR citation must be restored once
  that decision lands.
